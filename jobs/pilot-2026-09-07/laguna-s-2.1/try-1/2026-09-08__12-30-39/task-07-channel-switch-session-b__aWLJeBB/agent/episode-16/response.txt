Now I can see the defect clearly. The `ensureSession` function uses `ON CONFLICT (id) DO NOTHING`, which means if the session already exists (from the first channel), it does nothing - including not updating the `channel_id`. This is exactly the bug: the session's channel never gets updated when the viewer switches channels.

The fix is to change `ON CONFLICT (id) DO NOTHING` to `ON CONFLICT (id) DO UPDATE SET channel_id = EXCLUDED.channel_id` (and possibly update `last_activity_at` as well).
